# Карточки слов: спецификация (design)

Дата: 2026-10-05
Статус: утверждено в обсуждении, ожидает финального ревью

## 1. Цель

Личное приложение для изучения английского по карточкам: выбор темы → показ слова/фразы с озвучкой → перевод на русский с озвучкой → следующая карточка. Главное — простота и возможность заниматься в пути: и глядя на экран, и с выключенным экраном в наушниках.

Некоммерческий проект: без регистрации, без сервера с базой данных, с нулевой стоимостью эксплуатации.

**Основное устройство: iPhone** (Safari / PWA на главном экране, iOS 17+). Android и десктоп поддерживаются «бесплатно» как веб, но приоритет проверки — iPhone.

## 2. Архитектура

```
Компьютер (автор контента)                   Хостинг (бесплатно)         Телефон
content/*.csv ──► build_content.py ──► JSON + mp3 ──► GitHub Pages ──► PWA
                  (проверка, озвучка                                  ├─ офлайн-кэш наборов
                   только новых карточек)                             └─ профили/прогресс в IndexedDB
```

- **Клиент:** PWA на Vite + TypeScript + Preact + `vite-plugin-pwa` (Workbox).
- **Контент:** CSV-файлы в репозитории — единственный источник правды. SQLite не используется.
- **Озвучка:** генерируется один раз при сборке контента через `edge-tts` (бесплатные нейронные голоса Microsoft). Запасной вариант при недоступности — Google Cloud TTS (бесплатный лимит); остальная система от выбора TTS не зависит.
- **Хостинг:** GitHub Pages, деплой через GitHub Actions при `git push` в `main`.
- **Данные пользователя:** только на телефоне (IndexedDB через библиотеку `idb`). Синхронизации между устройствами нет.

## 3. Экраны и режимы

1. **Профили.** Список имён + «Добавить». Без пароля. У каждого профиля свой прогресс и настройки. При единственном профиле экран пропускается.
2. **Темы.** Темы → наборы по 20–50 карточек. У набора: трёхцветная полоска прогресса (новые / учу / выучено), значок «скачано», кнопка «Скачать набор». На главном экране — кнопка **«📅 Повторение на сегодня»**.
3. **Карточка (ручной режим).** Показ EN + автоозвучка → тап = переворот, RU + озвучка → кнопки «Знаю» / «Повторить» → следующая. Кнопка 🔊 повторяет звук, свайп влево — пропустить.
4. **Автопоказ (экран включён).** Цикл: EN текст+звук → пауза N → RU текст+звук → пауза N → следующая. Кнопки пауза / назад / вперёд / «⭐ трудная». Экран не гаснет (Wake Lock API).
5. **«В кармане» (экран выключен).** Тот же цикл, только звук. Управление с экрана блокировки и кнопками наушников (пауза, следующая, предыдущая); на экране блокировки отображается текст текущей карточки. В конце набора — повтор или остановка (по настройке).
6. **Настройки (на профиль).** Пауза: 3 / 5 / 8 / 10 с. Направление: EN→RU или RU→EN. Порядок: подряд / вперемешку. Повтор английского: 1 или 2 раза. Скорость: 0.8× / 1× / 1.2× (через `playbackRate`). Экспорт / импорт прогресса (JSON-файл).

**Выбор карточек при запуске набора:** «Весь набор», «Новые и трудные» (коробки 0–2). Отдельно — «Повторение на сегодня» по всем темам (карточки, у которых наступил срок).

**Вне рамок первой версии:** поиск, ввод ответа с клавиатуры, игры, статистика по дням, синхронизация, редактирование контента в приложении.

## 4. Прогресс: система Лейтнера

Для пары (профиль, карточка) хранится: `box` (0–5), `nextDue` (дата), `lastSeen`, `starred`.

| box | Смысл | Интервал до следующего показа |
|---|---|---|
| 0 | новая | — |
| 1 | трудная | 1 день |
| 2 | | 3 дня |
| 3 | | 7 дней |
| 4 | | 14 дней |
| 5 | выучено | 30 дней |

- «Знаю»: `box = min(box + 1, 5)`, `nextDue = сегодня + интервал(box)`.
- «Повторить» и «⭐» в автопоказе: `box = 1`, `nextDue = завтра`.
- Автопоказ и режим «в кармане» не меняют `box` (кроме ⭐), обновляют только `lastSeen`.
- Полоска прогресса: новые = box 0, учу = box 1–4, выучено = box 5.
- Прогресс привязан к постоянному `id` карточки. Правка текста не сбрасывает прогресс. Прогресс удалённых карточек игнорируется.

## 5. Контент и сборка

### Структура репозитория

```
content/
  topics.csv
  <topic-id>.csv
tools/
  build_content.py
  tests/
app/
  src/ ...
  public/content/        ← генерируется скриптом (index.json, <topic-id>.json, audio/*.mp3)
.github/workflows/deploy.yml
```

### Формат CSV

UTF-8, разделитель `;`, первая строка — заголовок.

`content/topics.csv`:
```
id;title;description;order;en_voice;ru_voice
top-500-words;500 частых слов;Самые нужные слова с примерами;1;;
```
`en_voice` / `ru_voice` необязательны. По умолчанию: `en-US-AriaNeural`, `ru-RU-SvetlanaNeural`.

`content/<topic-id>.csv`:
```
id;set;en;ru;en_ex;ru_ex
pv001;1;get up;вставать;I get up at seven.;Я встаю в семь.
```
- `id` — уникален глобально (по всем темам), постоянный.
- `set` — номер набора (целое ≥ 1).
- `en`, `ru` — обязательны. `en_ex`, `ru_ex` — необязательны (пустые для тем-фраз).

### Озвучка

- На карточку два mp3: EN-сторона (`en` + пауза ~0.6 с + `en_ex`) и RU-сторона (`ru` + пауза + `ru_ex`). Части склеиваются через ffmpeg.
- Имя файла: короткий хэш (sha1, 12 символов) от `голос + текст стороны` → `audio/<hash>.mp3`. Существующие файлы не перегенерируются; файлы, на которые никто не ссылается, удаляются.
- Формат: mp3, моно, 48 кбит/с.
- Файлы тишины для пауз (`silence_1s.mp3` и т. п.) генерируются скриптом один раз.
- mp3 коммитятся в git (локальная генерация надёжнее, чем из GitHub Actions).

### `python tools/build_content.py`

1. Валидация CSV: кодировка, заголовки, уникальность `id`, обязательные поля, `set` — целое, тема из `<topic-id>.csv` есть в `topics.csv`. При ошибке — сообщение «файл:строка: причина», выход с кодом ≠ 0, ничего не записывается.
2. Генерация недостающих mp3 (до 3 попыток на файл). Неудачные — в итоговый отчёт, выход с кодом ≠ 0.
3. Запись `index.json` (темы, наборы, число карточек, `contentVersion` = хэш всего контента) и `<topic-id>.json` (карточки с путями к аудио).

### Публикация

`git push` → GitHub Actions: `npm ci && npm run build` в `app/` → деплой на GitHub Pages. Приложение при запуске сверяет `contentVersion` и показывает новые темы; ранее скачанные изменённые наборы докачиваются.

### Первичное наполнение

Подготавливает Claude, пользователь проверяет:
- 500 частых слов (наборы по 50, слово + пример)
- 100 бытовых фраз (магазин, кафе, дорога, отель)
- Фразовые глаголы (глагол + пример)
- Наречия и связки (слово + пример)
- Неправильные глаголы (go – went – gone + пример)
- Small talk и вежливость (фразы)

## 6. Устройство приложения

```
app/src/
  domain/          чистая логика, без зависимостей от браузера
    leitner.ts       applyAnswer(), isDue(), интервалы
    selection.ts     выбор карточек: весь набор / новые+трудные / на сегодня; перемешивание
    sequence.ts      карточки + настройки → сценарий шагов воспроизведения
  data/
    content.ts       загрузка index.json и тем
    db.ts            IndexedDB: profiles, settings, progress; экспорт/импорт JSON
    offline.ts       скачивание набора в Cache Storage, статус «скачано»
  player/
    AudioEngine.ts   воспроизведение сценария, Media Session, события для UI
  ui/
    screens/         Profiles, Topics, Card, Player, Settings
    components/
```

**Сценарий** (`sequence.ts`) — список шагов:
`{ kind: 'audio', url, cardId, side }` | `{ kind: 'silence', seconds }`.
Автопоказ и «в кармане» используют один и тот же `AudioEngine`; автопоказ дополнительно рисует текущую карточку и держит Wake Lock.

**AudioEngine:**
- один `HTMLAudioElement`, шаги проигрываются по событию `ended`; паузы — mp3-файлы тишины, чтобы аудиосессия iOS не прерывалась при выключенном экране;
- Media Session: метаданные = текст текущей карточки; обработчики play, pause, nexttrack, previoustrack (переход к следующей/предыдущей карточке, а не шагу);
- старт только по нажатию ▶ (ограничение автовоспроизведения в браузерах).

**Офлайн:** оболочка приложения кэшируется Workbox (precache). Аудио: стратегия cache-first; «Скачать набор» заранее кладёт все mp3 набора в Cache Storage.

## 7. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| mp3 не загрузился | 1 повтор → пропуск карточки. В ручном/автопоказе — сообщение «нет звука — скачайте набор»; «в кармане» — тихо дальше |
| Нет места при скачивании набора | Сообщение, частично скачанное удаляется |
| `index.json` недоступен (офлайн) | Используется закэшированная версия |
| Карточка удалена из контента | Её прогресс игнорируется |
| Wake Lock не поддерживается | Автопоказ работает, экран может погаснуть — без ошибки |
| Импорт повреждённого JSON | Сообщение, текущие данные не меняются |

## 8. Тестирование

- **Python (pytest):** валидация CSV (каждое правило), хэш-имена, определение «что озвучивать» и «что удалить», формирование JSON. TTS подменяется заглушкой.
- **TypeScript (Vitest):** `leitner`, `selection`, `sequence` — полное покрытие; `db` — через `fake-indexeddb`.
- **Ручной чек-лист на iPhone** (приложение установлено на главный экран): воспроизведение при выключенном экране, управление с экрана блокировки и наушников, текст карточки на экране блокировки, офлайн-режим в авиарежиме, Wake Lock в автопоказе, обновление контента после деплоя.

## 9. Риски

- **`edge-tts` неофициальный** — может перестать работать. Смягчение: TTS изолирован в одной функции скрипта, замена на Google Cloud TTS не затрагивает остальное.
- **Фоновое аудио в PWA на iOS** исторически нестабильно. Смягчение: непрерывный поток через один аудиоэлемент с mp3-тишиной; раннее прототипирование и проверка на iPhone **первым делом** после каркаса приложения.
- **Очистка хранилища браузером.** Смягчение: установка на главный экран + экспорт/импорт прогресса.
